# feishu-pocket-ledger · 飞书随手记账

在飞书单聊中记账，账单直接保存到飞书多维表格。支持按年管理账本、按月汇总、自动分类、金额更正和原生图表。手机和电脑上的飞书都能使用；后台程序需要持续运行并联网。

## 功能

- **一年一个账本，每月一个子表**：复用已有年度文件及月份表，不重复创建链接。
- **逐笔明细与每日汇总**：同一天同一分类自动累加，回复中列出原有项目、本次新增和汇总后金额。
- **月末总计**：各分类及整月支出自动更新；金额为0的格子留空。
- **分类确认**：优先使用括号或“属于……”指定的分类，其他消费按关键词匹配；不确定时询问。
- **金额更正**：修改原消费，保留不计入支出的更正记录；目标不唯一时要求补充信息。
- **账单链接**：支持完整年份、两位年份和“上个月”等查询。
- **原生仪表盘**：月份分类饼图、每日支出柱状图、全年各月支出对比；创建月份账单时同步补齐图表。
- **个人专用**：只处理配置所有者发给机器人的单聊文本消息。

## 快速开始

### 1. 准备环境

需要 Python 3.9+ 和官方 [飞书 CLI](https://github.com/larksuite/cli)。后台支持 macOS / Linux（使用 `fcntl` 防止同一目录重复启动），无需额外 Python 运行依赖。

```sh
git clone https://github.com/qishibufatigue22/feishu-pocket-ledger.git
cd feishu-pocket-ledger
python3 --version
lark-cli --version
```

### 2. 配置飞书应用与授权

没有应用时运行以下命令，按页面指引创建并绑定；已有应用时，先使用 `lark-cli config init --help` 查看绑定方式。

```sh
lark-cli config init --new
lark-cli auth login --domain base --scope drive:drive:readonly
lark-cli auth status --json --verify
```

在飞书开放平台为自建应用开启机器人能力，配置读取单聊消息、以应用身份回复消息及多维表格相关权限。订阅 `im.message.receive_v1`，选择长连接接收事件，并按后台要求发布应用及设置可用范围。

账本操作使用授权用户身份，消息接收和回复使用机器人身份。创建图表还需要仪表盘、字段、视图相关权限；以 CLI 返回的缺失权限提示为准。

### 3. 创建本机配置

```sh
cp config.example.json config.json
```

填写 `owner_open_id`，值来自 `auth status` 返回的 `identities.user.openId`。如果使用特定 CLI profile，填写其名称；否则 `profile` 保持 `null`。

```json
{
  "owner_open_id": "ou_your_open_id",
  "profile": null,
  "years": {}
}
```

`years` 和 `dashboards` 由机器人维护，保存年度文件及仪表盘的资源标识。保留并备份此配置，便于重启后找到既有账本与待分类消费。

### 4. 启动

```sh
python3 robot.py
```

看到“飞书消息监听已就绪”后，在飞书里给机器人发送“帮助”。`Ctrl+C` 可正常停止程序。

### macOS 常驻运行

如果希望退出聊天或终端后机器人仍运行，可在完成配置后安装当前用户的登录启动服务：

```sh
python3 scripts/install_launch_agent.py
```

安装器把运行代码复制到 `~/Library/Application Support/feishu-pocket-ledger/`，避免后台服务依赖“文稿”目录的交互式访问权限；首次安装同时复制 `config.json`，以后更新保留该目录的配置与消息去重记录。运行目录权限为700，私有配置权限为600。

服务在用户登录时启动，异常退出自动重启。更新仓库代码后再次运行安装器即可更新运行副本。安装后不要再手工启动项目目录里的另一份机器人，避免同一账本被两个实例处理。

```sh
launchctl print gui/$(id -u)/com.feishu-pocket-ledger.robot
tail -f "$HOME/Library/Application Support/feishu-pocket-ledger/.logs/robot.stderr.log"
```

停用常驻服务：`launchctl bootout gui/$(id -u)/com.feishu-pocket-ledger.robot`。卸载时还需移除 `~/Library/LaunchAgents/com.feishu-pocket-ledger.robot.plist`；删除运行配置前请先备份。

常驻服务不能让关机、休眠或断网的电脑继续接收消息。需要全天在线时仍应部署到持续联网的主机。

## 聊天示例

| 目的 | 消息示例 |
| --- | --- |
| 创建月份账单及图表 | `新建2026年9月账单` |
| 查询账单链接 | `把26年10月账单链接发给我` |
| 查询上月账单 | `把上个月账单链接发给我` |
| 当天消费 | `午饭20` |
| 指定日期 | `10月23 高铁36` |
| 跨年补记 | `2025-10-03 地铁3` |
| 相对日期 | `昨天 外卖25` |
| 指定分类 | `10月30乳胶手套3.08（日用品）` |
| 文字指定分类 | `乳胶手套3.08 属于日用品` |
| 更正金额 | `不对，交通费是14.99` |
| 明确更正目标 | `11月2日 交通费15改成14.99` |
| 去掉重复消费 | `不对 10月24 iCloud重复了` |
| 撤销一笔消费 | `撤销10月24 iCloud28` |
| 确认再次消费 | `再记一笔 10月24 iCloud28` |
| 单独补建月份图表 | `创建9月图表` |
| 补齐已有月份图表 | `更新仪表盘` |

无日期时使用**消息发送时的北京时间**。只写月日使用消息发送时的年份，只写“3日”使用当月；跨年请写完整年份。新建或打开其他月份不改变默认记账日期。

不确定分类时回复分类名称或1—9，也可回复“取消”。先处理当前待分类消费，再发下一笔；重新发送同一笔并附上分类，也可完成该笔分类。

## 分类

| 大类 | 子类 |
| --- | --- |
| 固定费 | 房租/物业水电、基金 |
| 流动费 | 伙食费、日用品、零花钱、交通 |
| 特别备用金 | 维修、旅行、生日 |

餐厅归伙食费，高铁、共享单车等归交通，iCloud、GPT / ChatGPT 归零花钱。明确指定的分类优先于自动匹配。分类使用固定规则，不调用外部模型；如“盒马”这类不明确的商户名仍会询问。

## 重复消息与撤销

断网后可能补收此前发送的消息。程序在回复成功后持久化已处理的消息ID，重启后不会重复回复这些事件。即使重发产生了不同消息ID，同一天、同项目（忽略英文大小写）、同金额的消费也会提示疑似重复，不自动新增；确实又消费了一笔时，用“再记一笔”明确确认。

“重复了”只会在找到两笔及以上同项目、同金额的消费时撤销一笔；如果金额不同或目标不明确，会要求补充日期、项目和金额。只有一笔时不会因再次说“重复了”继续扣除。“撤销”可移除一笔明确的消费，原记录保留为已撤销状态，另留不计入支出的审计记录。回复会列出原有项目、原有合计、本次扣除和调整后的分类合计。

## 数据结构与图表

```text
2026年账本
├── 消费明细：每笔消费、分类状态、更正记录
├── 9月账单：每日分类支出 + 底部总计
├── 10月账单
└── 2026年支出分析：饼图、每日柱状图、全年月度对比
```

图表直接读取“消费明细”，仅汇总状态为“已入账”的金额，排除待分类、已取消、更正审计行，避免重复计算月份表的总计行。“月份”通过 `LEFT([日期],7)` 公式自动生成。

通过机器人记账、更正，或直接修改“消费明细”后，图表自动更新，可能有同步延迟。**只手动修改月份汇总表，不会改变图表**。仪表盘中也有数据来源与更新说明。

手工修改明细不会立即触发每日、月度汇总表重算；当前没有监听表格变更事件，建议通过机器人更正。也可通过以下命令补齐已有月份图表：

```sh
python3 dashboard_setup.py
```

## 运行与隐私说明

- GitHub 负责版本管理，**上传代码不会让机器人自动在线**。电脑关机、休眠或断网后，机器人无法及时处理消息；全天使用需要持续在线的服务器。
- 不使用本地 SQLite 保存账单；消费数据在飞书中，本机仅保留资源映射配置，程序处理时会读取明细到内存。
- CLI 管理的应用密钥、登录令牌、`config.json`、授权二维码、日志都不应上传。仓库只提供配置示例。`config.json` 还保存已处理的消息ID（不保存消息正文或消费金额），迁移机器时应一并安全迁移。
- 不要在多台机器同时处理同一个账本。本地文件锁只能阻止同一目录重复启动，不能提供跨主机锁。
- 写入后会等数据实际可读，再使用同一份明细计算日/月汇总，汇总确认写入后才回复成功。网络超时或同步确认失败时，先核对明细，避免再发一条新消费造成重复。
- 本项目仍需针对部署账号完成飞书权限与消息收发联调；CLI 授权过期或权限变化时需在运行机器上重新处理授权。

## 自然语言记账助手

可以直接发送：

- “昨天打车36，咖啡22，帮我记一下。”
- “上周吃饭花了多少？哪天最多？”
- “这个月花得最多的三类。”
- “昨天那笔打车改成32。”

目前由本地规则识别常见意图，不需要模型 API 或密钥。查账只统计本人已入账明细；周按周一到周日计算。批量记账先检查所有项目、金额和分类，分类不明确时请用括号补充。每笔仍独立查重并保存；飞书中途写入失败时，已成功的笔数不会回滚。更正必须定位唯一一笔，同类但不同名的消费不会被误改。

## 规则驱动财务 Agent

当前结构：

- `agent/intents.py`：解析意图、日期、金额；复用自然语言规则。
- `agent/orchestrator.py`：管理追问、任务恢复、选项选择和分类规则确认。
- `agent/tasks.py`：解析“第二笔”“36元的”等选择。
- `tools/ledger.py`：记账、更正、撤销及业务校验；`tools/analytics.py` 精确统计；`tools/charts.py` 图表入口。
- `storage/feishu.py`：飞书账本存取和写入核验。
- `storage/state.py`：独立的“记账机器人配置”多维表格，保存当前任务与已确认的个人规则，不写入年度消费合计。
- `knowledge/categories.py`：基础分类、关键词和别名。
- `adapters/feishu_bot.py`：消息收发、去重、连接管理。
- `main.py` / `robot.py`：启动入口；后者保留兼容性。

多笔更正或不同金额的撤销匹配会先列出候选，再接受“第二笔”“36元的”等回复；“取消这个操作”会结束任务。候选记录在执行前重新校验，金额或分类发生变化时不继续修改。任务存到飞书，程序重启后可以接着处理；写入开始前保存执行事件，以相同消息ID恢复，继续使用已有去重和金额核验。

给待分类消费选择分类后，机器人会询问是否记住“项目名→分类”。回复“记住”才持久保存，回复“不用记住”只保留本次入账。个人规则按完整项目名匹配；不会未经确认就把整家超市永久归到伙食费。明确指定的分类优先；“忘记分类规则盒马”可删除已保存规则。

Agent 仍使用本地规则，不接大模型或向量数据库，不宣称能理解任意表达。常驻版的资源映射和配置以运行目录为准；新的配置表token保存在运行目录私有 config.json 中。后续需求、变更按项目记录约定追加到飞书文档和 CHANGELOG.md。
